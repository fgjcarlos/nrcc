## Identity

- **Name:** nrcc (Node-RED Control Center)
- **Module:** `github.com/fgjcarlos/nrcc`
- **Description:** Linux-only Node-RED control center. A single Go binary embeds a
  React/TypeScript frontend and supervises a Node-RED child process. Provides
  authentication, metrics, audit, backups, settings management, and dashboard surfaces.
- **License:** Apache License 2.0 (`LICENSE`)
- **Build constraint:** Linux-only at compile time (see
  `docs/adr/0004-linux-only-build.md`). Uses POSIX-only syscall symbols
  (`syscall.Flock`, `syscall.Stat_t`, `syscall.O_NOFOLLOW`, `/proc/stat`,
  `syscall.Sysinfo`, lockfiles) that do not exist on Windows or macOS.

## Language policy

All repository-maintained technical artifacts are written in **English**.
The `tools/langscan` scanner enforces this and runs advisory-only in CI
(`.github/workflows/language-policy.yml`). User-visible product copy is
deferred to the i18n catalog introduced by issue **#767**; until then
user-facing strings in `frontend/src/**` may carry the existing Spanish copy.

Exempt paths (scanner does not report by design):

- `frontend/src/**` and `frontend/e2e/**`
- `auditoria/**`
- `tools/langscan/**`
- `node_modules/`, `vendor/`, generated files, build artefacts

When the scanner reports a finding, the documented options are: translate,
add an exemption marker (`// l10n: <reason>`), or move the artifact into an
excluded path category.

## Workflow

- **Trunk-based** against `main`, short-lived branches, squash merges.
- **Branch prefixes:** `fix/`, `feat/`, `chore/`, `docs/`, `refactor/`,
  `test/`, `ci/`.
- **Conventional commits** (`type(scope): subject`); PR title follows the
  same format.
- **One work-unit per commit** with the agreed review budget (typically 400
  authored lines per AGENTS.md).
- **One concern per PR.** Split when a change spreads.
- **Reference issues** in the PR body (`Refs #N` for related, `Closes #N`
  for the one being resolved).
- **Let CI run.** Backend and frontend gates must be green before review.

For substantial work (multi-step implementation, multi-file changes, or
anything that needs recoverable state) track tasks under
`odd/tasks/<feature-name>.md` and mirror them in a visible todo list before
the first write (Organic Driven Development workflow).

## SDD / OpenSpec alignment

This project follows OpenSpec-driven development. Capability work follows the
phase ordering declared in `openspec/config.yaml`:

```
sdd-init → spec → design → plan → implement → verify → review → deliver
```

- `sdd-init` produces `openspec/config.yaml` and `openspec/project.md` (this
  file). Refreshed only on SDD session retry or when the user explicitly
  asks for a new project initialization.
- `spec` adds `openspec/specs/<capability>/spec.md`.
- `design` adds `openspec/specs/<capability>/design.md`.
- `plan` writes `odd/tasks/<feature>.md`.
- `implement` makes work-unit commits under the 400-line review budget.
- `verify` runs the testing matrix declared below and captures receipts.
- `review` runs judgment-day dual review when triggered.
- `deliver` opens a PR with the issue-first checks from the `branch-pr` skill.

**Strict TDD is required.** A failing test must exist before implementation.
CI gates verify the test runner outputs match the matrix declared in
`openspec/config.yaml`.

**Delivery strategy: ask-on-risk.** When review-budget risk requires a
delivery decision, the orchestrator pauses and asks the user instead of
inventing a chain strategy or a `size:exception` exception.

## Testing capabilities (matrix)

The complete testing matrix is declared in `openspec/config.yaml` under
`testing.runners`. The summary:

| Surface | Tool | Command | Required at phase |
| --- | --- | --- | --- |
| Backend unit + race | `go test` | `go test -race -count=1 -timeout 20m ./...` | implement, verify, review |
| Backend lint | `golangci-lint` | `golangci-lint run --config=.golangci.yml ./...` | verify |
| Frontend unit | Vitest | `pnpm --filter frontend test --run` | implement, verify |
| Frontend lint | ESLint | `pnpm --filter frontend lint` | verify |
| Frontend typecheck | TypeScript | `pnpm --filter frontend typecheck` | verify |
| Frontend e2e | Playwright | `pnpm --filter frontend test:e2e` | user-facing changes, auth flows, new e2e capabilities |
| CI workflow | GitHub Actions | `.github/workflows/pr.yml` | verify (gate) |
| Language policy | `go run ./tools/langscan` | `.github/workflows/language-policy.yml` | verify (advisory) |
| i18n coverage | `node frontend/scripts/i18n-coverage.mjs` | `.github/workflows/i18n-check.yml` | verify (i18n-impacting changes) |

Backend conventions:

- Race detector enabled by default in CI.
- Table-driven tests where useful.
- Environment contract tests under `internal/service/env_contract_test.go`.
- Linux-only build; macOS/Windows builds are intentionally unsupported.

Frontend conventions:

- Vitest + `@testing-library/react` + jsdom for unit tests.
- MSW for HTTP mocking.
- Playwright for e2e flows (auth, dashboard, security, i18n, smoke, stack).
- OpenAPI → TypeScript codegen via `openapi-typescript ../docs/openapi.yaml`.
- Shared test helpers under `features/<name>/__test-utils__/`.

## Review budget

- Default: **400 changed lines per work-unit commit / PR slice**.
- Phases that would exceed the budget MUST pause and ask the user
  (`ask-on-risk`) for a delivery decision; chaining and exceptions are
  user-consent gates.

## Human-controlled gates (always pause, regardless of mode)

These gates ALWAYS pause for explicit user consent, even in `auto` mode:

- Consent / authorization requests.
- Security-sensitive changes (auth, secrets, TLS roots, audit).
- Destructive or publishing operations (releases, public installers).
- Ambiguous scope or unresolved product copy.
- `size:exception` PRs over the 400-line review budget.
