# Issue #949 — Force `minimatch` to the patched 11.x line so the security update resolves

## Objective

Issue [#949](https://github.com/fgjcarlos/nrcc/issues/949) reports that
Dependabot's `npm_and_yarn in /frontend for minimatch` security-update job
fails on `main` with `security_update_not_possible`: the highest version it
can install is `3.1.5`, while the earliest fixed version is `11.0.1`.

- Issue: <https://github.com/fgjcarlos/nrcc/issues/949>
- Branch: `fix/949-minimatch-11`
- Base: `origin/main` = `ebf0b9c`

## Problem and why it matters

`frontend/pnpm-lock.yaml` resolves `minimatch` at `10.2.6`, `5.1.9` and
`3.1.5`. Every one of them is below the patched line of
[GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)
(moderate, denial of service via globparts amplification), whose vulnerable
range is `<11.0.1` and whose patched range is `>=11.0.1`. The audit reports
it over 39 paths, the `eslint` and `glob` subtrees being the largest.

The repository's `pnpm audit --audit-level high` gate does not see the
finding (the advisory is moderate), so the gate stays green while the
dependency stays un-remediated.

Two conditions keep the automated path closed, the same way #920 kept it
closed for `fast-uri`:

1. **The dependency ranges.** The consumers ask for `minimatch` 3.x, 5.x and
   10.x, so the patched 11.x line is not installable without an override.
2. **The release-age window.** `11.0.3` was published on 2026-10-28, so it
   is inside the package manager's release-age window. The
   `minimumReleaseAgeExclude` list is the escape hatch for that window and
   has no `minimatch` entry yet.

## Authorized policy and constraints

- The override expresses the patched floor (`>=11.0.1`) and keeps the
  dependency on the 11.x line everywhere.
- The release-age exclusion names the resolved version, so the remediation
  does not depend on the release-age window.
- The lockfile is regenerated by the package manager, never edited by hand.
- The consumers of `minimatch` (`eslint`, `@eslint/config-array`, `glob`,
  `js-yaml`, `serve-handler`) must keep working: the lint gate, the
  typecheck, the unit suite, the build and the browser suite are the
  proof.
- Repository language rule: every artifact in this feature is written in
  English (see `AGENTS.md`).
- No merge, no issue-label change, no issue closure: those stay human
  decisions.
