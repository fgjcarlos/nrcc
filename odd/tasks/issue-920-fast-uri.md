# Issue #920 — Refresh `fast-uri` to 4.2.3 so the Dependabot security update resolves

## Objective

Issue [#920](https://github.com/fgjcarlos/nrcc/issues/920) reports that
Dependabot's `npm_and_yarn in /frontend for fast-uri` version-update job
fails on `main` with `security_update_not_possible`: the highest version
it can install is `4.2.1`, while the earliest fixed version is `4.2.3`.

- Issue: <https://github.com/fgjcarlos/nrcc/issues/920>
- Branch: `fix/920-fast-uri`
- Base: `origin/main`

## Problem and why it matters

`ajv@8.18.0` depends on `fast-uri@^3.0.1`. The repository overrides that
range to a 4.x line, because the 3.x line carries the published
advisories:

- `GHSA-w74x-v6f9-j3xg` (CVE-2026-110306, medium, URI scheme spoofing)
- `GHSA-wjr9-j795-jxcr` (CVE-2026-110180, medium, host confusion)
- `GHSA-xhq7-xmqj-769h` (CVE-2026-110095, low, path equivalence)
- `GHSA-333x-w4r6-6crp` (CVE-2026-110725, low, scheme injection)

`frontend/pnpm-workspace.yaml` expresses that intent with

```yaml
overrides:
  fast-uri: '>=4.2.1'
```

and the frontend lockfile resolves `fast-uri@4.2.1`, which is below the
patched `4.2.3`. The repository's own `pnpm audit --audit-level high`
gate does not see the finding (the advisories are medium and low), so the
gate stays green while the dependency stays un-remediated.

The reason the automated path is closed is the release-age policy of the
package manager: `4.2.3` was published on 2026-10-19 and, at the time
of the Dependabot run, it was still inside the release-age window, so the
newest version pnpm was allowed to install was `4.2.1`. Dependabot
therefore reported `security_update_not_possible` with
`latest-resolvable-version: 4.2.1` and
`lowest-non-vulnerable-version: 4.2.3`.

The `minimumReleaseAgeExclude` list of the workspace file already carries
the entries that must bypass that window (`js-yaml`, `@babel/core`,
`brace-expansion`, `daisyui`). Its `fast-uri@3.1.3` entry is stale: no
3.x version is in the tree any more, since the override forces the 4.x
line.

## Authorized policy and constraints

- The override keeps expressing the intended floor, and that floor moves
  to the patched version: `>=4.2.3`. The override cannot be dropped,
  because `ajv@8.18.0` asks for `^3.0.1` and the 3.x line is the
  vulnerable one.
- `minimumReleaseAgeExclude` names the version that is actually
  resolved (`fast-uri@4.2.3`), so the remediation does not depend on the
  release-age window.
- The lockfile is regenerated by the package manager, never edited by
  hand.
- Repository language rule: every artifact in this feature is written in
  English (see `AGENTS.md`).
- No merge, no issue-label change, no issue closure: those stay human
  decisions.
