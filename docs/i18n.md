# Internationalization

NRCC uses English as the canonical UI source and Spanish as its first maintained translation. Catalogs and the runtime live in `frontend/src`; this guide describes the repository contract rather than a translation tool workflow.

## Locale model

Catalogs are JSON files under `frontend/src/locales/{en,es}`. The browser stores the selected locale in `localStorage` under `nrcc.locale`; unsupported or absent values fall back to `en`.

```ts
const { t } = useT();
t('auth:login.submit');
```

See [catalog operations](../frontend/src/i18n/MAINTAINER.md) for maintainers and the [locale directory README](../frontend/src/locales/README.md) for contributor steps.

## Namespace conventions

Use the smallest capability namespace. The ten namespaces are:

- `auth`: login, setup, sessions, users, and access control.
- `backups`: backups, restore, scheduling, and recovery status.
- `common`: short shared actions and states only, such as Save or Cancel.
- `configuration`: Node-RED configuration and security settings.
- `dashboard`: overview cards, runtime state, and system health.
- `env-vars`: environment variables and `.env` editing.
- `files`: managed file browsing and file actions.
- `flows`: flow import, export, and flow-management messages.
- `libraries`: npm library discovery and management.
- `updates`: Node-RED update availability and apply status.

Feature-specific validation and errors remain below their feature namespace, for example `auth.errors.invalidCredentials`; do not add them to `common`.

## Fallback contract

English defines the full key set. Spanish must contain every English key and every Spanish value must be non-empty. The runtime falls back to English for an unavailable locale, but missing translations are a catalog defect caught before merge.

```json
{ "submit": "Sign in" }
```

## How to add a key

1. Choose the owning namespace rather than adding feature copy to `common`.
2. Add the same key to `en/<namespace>.json` and `es/<namespace>.json`.
3. Use `t('<namespace>:<key>')` in the component.
4. From `frontend/`, run `pnpm i18n:check` and `pnpm i18n:coverage`.

```ts
const message = t('backups:restore.confirm');
```

## How to add a third locale

Create `frontend/src/locales/<locale>/` with all ten namespace files copied from English. Translate values, register the locale in `frontend/src/i18n/constants.ts` and resource configuration, then extend parity and E2E coverage for it. Do not treat browser detection as registration.

## How the CI guards work

[`i18n-check.yml`](../.github/workflows/i18n-check.yml) runs two blocking jobs on pull requests and pushes to `main`:

- `pnpm i18n:check` scans JSX text nodes under `frontend/src` for likely hardcoded product copy.
- `pnpm i18n:coverage` checks EN/ES key parity and non-empty Spanish values, writes [`i18n-coverage.md`](i18n-coverage.md), and uploads it as an artifact.

Run the same package scripts locally from `frontend/` before requesting review.

## Technical identifiers

Technical identifiers remain verbatim: API names, configuration keys, filenames, code snippets, and approved product names are not translated. The copy scanner has a deliberately narrow allowlist for these exact cases. Extend it only when a new identifier is stable, user-visible, and would otherwise be a false positive; ordinary UI prose belongs in a catalog.
